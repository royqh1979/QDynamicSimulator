# 普通结构重构

目标是让结构和职责保持长期合理，而不是用局部补丁、兼容层或平行模型维持旧实现。

## 1. 先证明需要重构

- 阅读 AGENTS.md、当前设计、相关实现和测试。
- 记录具体问题：重复事实、双向可写状态、职责错位、丑陋类型转换、无法维护的不变量或一致性漏洞。
- 区分设计缺陷与局部 bug；熟悉错误也要先找到当前根因。
- 不因某个类名不理想就扩大重构，不顺带修复无关问题。
- 仅讨论或审查时，不修改生产代码。

## 2. 定义目标模型

写清楚：

- 谁是每项语义的唯一权威；
- 对象分类、ID、名称和跨层互找方式；
- 所有权、非拥有引用和对象失效边界；
- 当前状态、历史事实、构建期对象和只读投影；
- 编辑、撤销/重做、复制粘贴、持久化和级联删除规则；
- 哪些旧类型、字段、接口和兼容路径必须删除。

需要专门审查时组合调用：

- 值语义/const 接口：`value-const-api-design`；
- 对象所有权/析构：`object-lifetime-ownership`；
- 线程/Worker：`thread-async-lifecycle`；
- 性能优化：`measured-performance-optimization`。

不要在这些领域复制另一套完整规则。

## 3. 先文档和评审

- 在 history 中建立带完整本地时间的重构计划，记录目标、范围、方法、步骤、非目标和验收边界。
- 同步当前设计文档，明确哪些内容是现状、哪些是待实施目标。
- 审查对象不变量、调用点、迁移顺序和测试覆盖。
- 得到用户认可后再实施；重构中证据改变设计时，先更新文档并复审。

## 4. 分阶段迁移

- 大改动使用独立分支，不直接在 master 上工作。
- 每个阶段只处理一个明确边界；有依赖的后续阶段从已完成阶段建立分支，并记录合并顺序。
- 优先进行完整垂直迁移：模型、控制器、视图、I/O、测试和 profile 同步更新。
- 不在中间提交中保留两套都可用的平行模型。
- 不为保留旧实现而复制兼容层；项目明确需要兼容时例外。
- 复用现有保存/加载、命令和查找通道，避免另建一套快照或一致性逻辑。

## 5. 验证行为而不只是编译

按适用范围覆盖：

- 正常路径、空状态、边界和错误；
- 创建、修改、删除、级联关系；
- 撤销/重做、复制粘贴和跨文档操作；
- QDS/XMILE 等持久化及旧历史结果；
- ID/名称映射和两套投影的一致性；
- 生命周期、取消和不同销毁顺序；
- 项目要求的性能 profile。

执行项目标准的 Release 后 Debug 全量构建和测试。不得删除不符合旧实现的合法场景；先判断是实现 bug 还是夹具错误。

## 6. 自我审核

- 搜索旧类型、旧接口、重复字段和兼容入口是否全部移除。
- 检查新代码是否仍有 ugly cast、重复转换或绕过权威状态的通道。
- 更新过时注释、设计和 profile，不以 history 代替当前设计。
- 检查 git diff、生成文件和工作区，不顺带修改无关内容。
- 完成后停止，等待用户审核；不自动继续下一阶段。

## 7. 提交、合并与收尾

只有用户明确批准后才提交、合并或推送。

- 每个阶段提交信息使用英文并表达实际结构变化。
- 合并后确认目标分支、工作区和必要验收。
- 计划完成时将 history 文件改为 `-done`，放弃时改为 `-abandon`，并更新全部引用。
- history 补充实际过程、设计修正和最终结果，而不只是原计划。
- 合并到 master 后删除已合并且不再需要的本地分支；使用 `git branch -d`，不要用强制 `-D` 删除含未合并工作的分支。
- 当前分支、仍有未合并依赖改动的分支不得删除。
- 远程分支不自动删除；删除远程分支需要另行明确授权。
- 删除本任务专用的临时构建、调试、profiler 和结果输出目录/文件，包括仓库外为本任务创建的目录；保留标准 Release/Debug 构建目录及正式文档/profile 记录。删除前确认路径和没有正在使用它们的进程。

## 完成检查

- [ ] 重构有实际设计证据，不是局部补丁堆积。
- [ ] 单一权威、对象边界和不变量已写清。
- [ ] history 计划、当前设计和评审记录同步。
- [ ] 旧实现和平行路径已按范围删除。
- [ ] 测试、适用 profile 和 Release/Debug 全量通过。
- [ ] 用户已批准提交/合并/推送，未越权操作。
- [ ] 完成计划已标记，引用无残留。
- [ ] 已合并本地分支安全删除，工作区无遗留临时产物。
