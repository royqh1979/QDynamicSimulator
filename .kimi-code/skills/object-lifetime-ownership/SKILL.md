# 对象所有权与生命周期

目标是让每个对象都有明确 owner，让每个非拥有引用都知道对象何时失效，并使析构安全不依赖偶然的创建或销毁顺序。

## 1. 建立所有权清单

逐项记录：

- 对象由谁创建、谁负责删除、是否存在 parent；
- 当前指针是所有者句柄、非拥有索引、弱引用还是即时查询结果；
- 是否跨层、跨兄弟对象或跨调用栈保存；
- 是否被容器、lambda、异步回调或公开接口长期持有；
- 对象删除、文档重置和所有者析构时会发生什么。

优先消除不必要的长期持有。能按 ID 重新查询或只在调用栈内完成的，不保存指针。

## 2. 保留清晰的所有权形式

- C++ 唯一对象使用 unique_ptr 和明确容器所有权。
- Qt 对象使用既有父子体系；所有者保存直接子对象的 raw 句柄可以是合理的。
- 不要用 shared_ptr<QObject> 替代 Qt 父子所有权。
- 不可变非 QObject 数据确需共享寿命时才使用 shared_ptr<const T>。
- 不把所有者、索引和弱引用都机械改成同一种智能指针。

## 3. 长期非拥有引用

- 对可能先于引用者销毁的 QObject，优先考虑 QPointer，并在每次解引用前检查。
- QPointer 不延长寿命，也不保护半析构派生对象。
- QPointer 不适用于 QVector、Document 等非 QObject 数据。
- 非 QObject 数据优先使用值、const 引用即时访问或明确共享所有权。
- 弱引用不能替代业务级联删除；例如删除实体时仍必须删除关联连接。

## 4. 审核 raw pointer 返回接口

不要只审查成员变量，也要审查公开和内部函数返回：

- 可廉价独立保存的容器优先值返回。
- 必然存在且不可复制的对象优先引用。
- 多态、唯一对象和可空查找可以保留 const raw pointer，但必须限制在当前调用栈。
- Qt 框架要求的所有权转移接口，例如创建 QMimeData，遵循框架契约。
- typedef、迭代器 operator->、std::get_if 和 variant alternative 也属于等价审查范围。
- 检查调用方是否在 Document 修改、移动、清空或删除后继续使用旧指针。

## 5. 不依赖精巧析构顺序

注意 C++/Qt 析构阶段：

- parent 的派生成员可能早于 QObject 基类中的 child 删除而销毁；
- 兄弟对象销毁顺序不能充当生命周期接口；
- 基类析构可能发信号，此时派生成员已销毁，但 QPointer 尚未必然清空；
- 自动 disconnect 不能覆盖“另一个兄弟已经失效”或“当前对象处于半析构”的情况。

需要由类自己封闭析构期行为，而不是让顶层窗口逐对 disconnect 接收方。

对 QGraphicsScene 等基类析构会清理对象并发通知的场景，可在派生析构入口 `blockSignals(true)` 且不恢复。不要在派生析构体中使用结束后自动恢复的局部 QSignalBlocker，否则基类析构仍会通知。Qt 的 `QObject::destroyed` 不受 blockSignals 阻止，QPointer 跟踪仍可工作。

显式会话 reset 与析构停止可以不同：前者允许业务通知，后者只停止工作并释放资源。

## 6. 批量删除与索引

- 单个删除先移出索引，再删除对象。
- 批量清空前先使 ID 索引、控制句柄和临时引用失效。
- 防止 clear 期间的通知重入并重新建立已失效索引。
- 若允许绕过所有者直接删除登记对象，必须同时使用弱索引或销毁注销机制；否则明确禁止这种外部删除。

## 7. 验证

使用确定性场景，而不是只等待随机崩溃：

- Controller/Scene/Panel 按不同顺序销毁；
- 所有者先销毁、观察者后销毁，以及反向顺序；
- 单独删除连接端点后的几何、绘制和样式查询；
- 选中对象时替换 Document；
- 运行中关闭、显式 reset 和析构；
- 统计析构期业务通知，确认没有半析构回调；
- 保留压力循环和可重复 profile，但不能把“多跑没崩”当作唯一证明。
