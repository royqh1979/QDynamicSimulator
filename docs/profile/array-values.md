# 数组堆句柄与元素访问 Profile

## 对比设计

基线为阶段一提交 `dea3337`：ArrayValue 直接保存 dimensions、shape、values 三个 QVector，依赖 QVector 写时复制。阶段二改为 ArrayValue 持有共享 ArrayData 堆对象，const 读取共享；非 const `values()` 在句柄不唯一时克隆 ArrayData，保持调用方修改结果副本不反写原值或 Run。

阶段二同时引入通用 ArrayElementView：参数只求值一次，维度映射只创建一次；相同布局直接行主序寻址，不同布局使用共享重排映射，不再为读取一个元素生成完整广播数组。Delay 与 mapped functions 复用该视图。

运行 Release：

```bash
cmake --build <RELEASE_BUILD_DIR> --target profile-array profile-delay --parallel
<RELEASE_BUILD_DIR>/tests/profile/profile-array.exe 100000 16
<RELEASE_BUILD_DIR>/tests/profile/profile-array.exe 100000 4
<RELEASE_BUILD_DIR>/tests/profile/profile-delay.exe 100 1000 16
```

`profile-array` 的两个参数是迭代次数和数组大小。身份读取与 16 层嵌套宏主要测量参数/栈槽传递，广播主要测量新数组发布，下标主要测量单个元素读取。所有 checksum 与基线一致。

| 16 | array_macro_nested_16 | 258.6621 / 246.7029 | 226.1216 / 237.2391 | -8.3% |
| 16 | array_broadcast | 52.7040 / 51.7333 | 58.1079 / 57.3970 | +10.6% |
| 16 | array_subscript | 41.4225 / 42.6061 | 40.0242 / 39.1157 | -5.8% |
| 4 | array_identity | 9.3069 / 9.4022 | 7.3291 / 7.3041 | -21.8% |
| 4 | array_macro_nested_16 | 253.9188 / 256.4322 | 226.5104 / 232.7014 | -10.0% |
| 4 | array_broadcast | 67.2786 / 67.0316 | 69.9357 / 71.5624 | +5.4% |

结论：共享句柄减少参数复制，身份读取和嵌套宏稳定受益；新数组发布增加 ArrayData 分配，广播场景稳定回退。不能将该设计称为所有数组操作的普遍加速。

## Delay 数组两轮对比

第一版 ArrayElementView 即使布局相同也创建映射和 strides，曾使数组 Delay 相比阶段一回退约 35%。改为相同布局直接寻址后，最终结果为：

| 场景 | 阶段一运行 ms | 阶段二运行 ms | 阶段一→二 ns/元素步（均值） | 变化 |
| --- | ---: | ---: | ---: | ---: |
| material_n_array | 1488.7886 / 1493.5718 | 958.1881 / 948.1921 | 931.988→595.744 | -36.1% |
| information_n_array | 1402.1998 / 1399.7401 | 880.9690 / 870.5321 | 875.606→547.344 | -37.5% |

相对最初功能基线 `a95eba4`，Material/Information 总耗时分别由 1555.0762/1459.5990 ms 的两轮均值降至 953.1901/875.7506 ms，约下降 38.7%/40.0%。checksum 完全一致。

代价是每次数组变量发布增加 ArrayData 分配：两个数组 Delay 场景的 C++ `operator new` 从每次 Run 13 次增至 2018 次，请求字节数由 64000 增至 8084000。当前负载下，消除重复求值和广播的收益明显大于分配成本；广播微基准说明该成本不能忽略。

标量场景未观察到一致回退：离散 RK4 由阶段一两轮 186.5642/185.2606 ms 变为 175.3959/178.9042 ms；连续 DELAY3 由 188.0947/188.5876 ms 变为 184.1661/189.3234 ms。其差异主要用于后续热点观察，不归因为数组优化的普遍收益。

## 广播回退归因实验

在 `perf/array-broadcast-analysis` 以 `93adc4f` 为当前基线，为 `profile-array` 增加 C++ `operator new` 计数，并分两步实验：

- A：仅把二元 elementwise 输出改为局部 QVector 构建后一次性发布，保留标量临时广播数组。
- B：在 A 上增加标量/数组直接计算路径，不再创建标量临时数组；数组本身仍执行原有维度校验。

| 数组大小 | 当前基线 ms | A ms | B ms | 基线→B |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 57.3802 / 57.9109 | 56.6429 / 57.0097 | 42.4599 / 41.3085 | -27.3% |
| 4 | 70.7636 / 72.7534 | 71.4853 / 70.7695 | 55.2661 / 55.4496 | -22.9% |

A 的两轮均值只改善约 1.4%/0.9%，说明重复 `values()` 检查不是主要成本。B 将每次迭代的 `operator new` 从 2 次降为 1 次、请求字节从 80 降为 40，证明被移除的临时数组确实对应一次 ArrayData 分配。

但 B 同时移除了临时 values 缓冲区及其 N 个 double 初始化，不能据此把阶段二回退单独归咎于 ArrayData。更早的 QVector COW 基线为 52.7040/51.7333 ms（16）和 67.2786/67.0316 ms（4）；B 反而比该旧实现快约 19.8%/17.6%。准确结论是：完整标量临时数组是当前最大的可避免成本，重复句柄检查影响很小；ArrayData 与 values 各自的独立贡献仍未由该实验分离。

Release 与 Debug 的 18/18 CTest 和完整 XMILE corpus 在 B 上通过；新增标量左乘和标量除以数组测试。

## 跨表示的同优化对照与操作级测量

为排除“旧实现也有标量临时数组”造成的归因混淆，另从 master `af25198` 建立 `perf/array-broadcast-cow-baseline`，在旧 QVector COW 表示上实施相同的局部 QVector 输出和标量直接计算。旧分支提交为 `8622cda`，不合并。

优化后的两个可执行文件交替运行。早期曾出现新句柄 4 元素约 200 ns/次的差距，但后续无法复现，不能作为稳定结论。最终固定 `8622cda` 与 `8064c90` 两个独立可执行文件，每组 300000 次迭代，正反向交替四轮：

| 场景 | 旧 COW 四轮 ms | 新句柄四轮 ms | 均值差异 |
| --- | --- | --- | ---: |
| A+1，16 元素 | 115.6785 / 115.2748 / 114.8387 / 118.9872 | 119.8044 / 121.4591 / 121.1201 / 123.2094 | +4.48%，约 17.3 ns/次 |
| A+1，4 元素 | 106.5429 / 108.1492 / 106.5525 / 111.7686 | 111.5092 / 111.9717 / 111.5978 / 113.1449 | +3.51%，约 12.7 ns/次 |
| A+A，16 元素 | 198.5992 / 196.3533 / 197.3094 / 197.7528 | 191.2543 / 194.4088 / 195.1683 / 195.7319 | -1.70% |
| A+A，4 元素 | 185.4288 / 186.2431 / 186.2038 / 188.9211 | 181.5747 / 184.4527 / 182.2788 / 185.3940 | -1.75% |

四轮均值分别为：A+1 旧 COW 116.1948/108.2533 ms，新句柄 121.3983/112.0559 ms（16/4）。可重复差距只有约 4%，不是早期约 40%；`A+A` 新句柄反而略快，说明不存在所有数组路径一致的固定回退。

`profile-array-operations` 进一步分离相关操作（无分配计数器的轮次）：

| 操作 | 旧 COW ns/次 | 新句柄 ns/次 | 差异 |
| --- | ---: | ---: | ---: |
| 空值创建，16 | 20.7827 / 21.1150 | 51.0757 / 51.1234 | 新句柄约 +30 ns |
| 直接复制，16 | 29.1443 / 28.7910 | 8.3451 / 8.5056 | 新句柄约快 20 ns |
| 带 values 发布，16 | 28.8468 / 28.0568 | 61.1339 / 61.9216 | 新句柄约 +33 ns |
| variant 复制，16 | 27.8899 | 9.9303 | 新句柄约快 18 ns |
| 完整计算并发布，16 | 66.8785 / 67.7352 | 100.9879 / 101.4551 | 新句柄约 +34 ns |
| 完整计算并发布，4 | 54.9931 / 53.4343 | 86.3831 / 86.2086 | 新句柄约 +32 ns |

为自定义 `operator new` 增加两次原子计数后，每次分配另增加约 7 ns，不能解释早期约 200 ns 的异常差距。共享句柄在直接/variant 复制中比三个 QVector 的 COW 复制更快，抵消了一部分 ArrayData 成本。

最终归因：

1. 标量临时 values 是两种实现共有的冗余，不是阶段二新增问题；消除它对两者都有明显收益。
2. 重复 `values()` 唯一性检查约 1% 影响，不是主因。
3. ArrayData 创建/发布约 30–34 ns/次，与稳定公式差距同量级，是新增固定成本；共享句柄复制更快会抵消一部分。
4. 早期大差距及不同构建间的变化不作为收益或回退依据。最终只使用可重复的差距，不宣称单次 malloc 或新表示解释了所有路径的全部耗时。

同优化后，新句柄每次迭代仍分配一个 ArrayData，旧 COW 没有该对象分配；这与微基准一致。旧 COW 的 0 次仅指该对象的 `operator new`，不表示 QVector values 没有 malloc。

## 正确性与寿命验证

- 24 层嵌套宏数组参数、ExecutionStack 扩容、数组计算不修改共享输入。
- 下标/切片、维度重排、广播、Apply-to-All、时间函数、随机函数和 Delay 数组参考序列。
- 非 const 修改从 Run 取出的数组副本仍不会反写 Run；历史采样值保持不变。
- Release 与 Debug 均构建 `all-test-targets`，18/18 CTest 和完整 XMILE corpus 通过。

## 后续建议

保留堆句柄与通用视图作为当前候选，是否提交由审核决定。后续先复用 Delay 速率工作区，再根据 profile 判断是否降低数组发布分配；不在本阶段引入 Arena 或更复杂的编译期临时槽管理。
