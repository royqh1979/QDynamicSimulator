# 延迟与平滑函数 Profile

## 负载与运行方法

本报告是新功能的固定基线，不包含优化前后对比，也不据单次波动宣称性能收益。

Release 环境为 Windows、GCC 8.1.0、Qt 5.15.18 静态构建。直接运行：

```bash
cmake --build <RELEASE_BUILD_DIR> --target profile-delay --parallel
<RELEASE_BUILD_DIR>/tests/profile/profile-delay.exe 100 1000 16
```

三个参数依次为每场景运行次数、每次运行步数和数组元素数。固定 DT=0.01、1000 步，SAVEPER 等于总时长，因此每次运行只保存首尾两个采样点。多阶 Material/Information 均为 N=8、T=8；Fixed 的 T=0.5，对应 50 个管道槽；连续 DELAY3 使用 RK4。数组场景包含 16 个独立元素，每个元素 8 级状态。

`random_initial` 使用 `RANDOM(0,1)` 作为初值，用于插桩检查初始化次数。所有场景检查 Completed、样本数和有限 checksum；相同负载的两轮 checksum 完全一致。编译与运行分开计时，运行时间包含最终结果查询。

CSV 字段包括场景、阶段、运行数、步数、元素数、状态 Level 数、总耗时、每运行/步/元素步纳秒数、checksum、`operator new` 次数及请求字节数。分配计数覆盖本可执行文件的全局 C++ `operator new/new[]`，不代表 Qt 内部直接使用 `malloc/realloc` 的全部内存分配。

## 阶段二：数组堆句柄与元素视图

数组 Delay 在阶段一基础上继续下降：Material 两轮为 958.1881/948.1921 ms，Information 为 880.9690/870.5321 ms，分别再降 36.1%/37.5%。相同布局直接寻址避免了完整广播与重复参数求值；每次 Run 的 ArrayData 分配增加是当前代价。完整前后数据、宏/广播/下标分化结果见 [数组堆句柄与元素访问 Profile](array-values.md)。

## 插桩与热点审查

另用独立 `-O3 -g -pg` 构建执行 `profile-delay 50 1000 8`，不覆盖正常 Release，也不将插桩耗时与上表直接比较。该轮包含 8 个场景、400 次 Run。

- `_mcount_private` 与 `__fentry__` 合计约 56.1% self-time，是插桩开销，不能当成生产热点。
- 排除插桩后，`Evaluator::delay`、`QVector<double>::detach/realloc`、数组坐标计算和 `delayRates` 出现在采样热点中。detach 调用包含写时复制检查，不等同于实际深拷贝。
- `RandomStreamState::stream` 恰好调用 50 次，等于 `random_initial` 的 50 次 Run；没有每步重新求值随机初值。该场景每次 Run 的分配仅由 13 增至 19，也未随 1000 步增长。
- 根据各场景调用路径，`delayRates` 应执行 700400 次；`QVector<double>::resize` 总计 702400 次，量级与延迟速率向量及其它少量数组分配一致。
- Fixed 在 50050 个实际步/终点求值中仍创建长度为全部状态槽的速率结果，尽管 Fixed 不使用微分速率。
- 离散 `material_n_rk4` 的 200050 次速率计算中，只有 50050 次 K1 用于状态推进，其余 150050 次结果未使用。
- 数组当前元素路径先求值输入/时间，又在元素选择阶段重复求值相同 AST；坐标转换也随元素步执行。这是冗余工作候选，不是数组状态语义的必要成本。

## 结论与后续候选

当前正确性门禁不依赖性能修改。后续若优化，应分别建立独立阶段和同场景基线：

1. Fixed 不进入微分速率计算，离散 N 在 RK4 中只计算实际使用的 K1。
2. 在 Run/阶段工作区复用速率向量，避免反复分配完整状态长度容器。
3. 数组当前元素直接选择已求值 Value，避免第二次输入/时间 AST 求值。
4. 将阶段状态复制与写时复制分离作为独立热点审查，不把 detach 次数直接当成内存复制量。

这些候选均未在本功能阶段实施；需要保持数值序列、初始化时点、错误前缀、数组元素独立性和 Euler/RK4 语义不变。
